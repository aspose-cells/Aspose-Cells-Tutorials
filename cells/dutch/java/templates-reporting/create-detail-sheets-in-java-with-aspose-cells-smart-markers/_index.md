# Detailbladen maken in Java met Aspose.Cells smart markers

Als je **detailbladen** moet maken in een Java‑applicatie, laat deze tutorial je zien hoe je dat doet met Aspose.Cells smart markers. Je ziet een compleet, uitvoerbaar voorbeeld dat **java create worksheets**, de **sheet name from field** afleidt, en **process data source** in slechts een paar regels code.

De gids behandelt alles van projectconfiguratie tot het opslaan van de uiteindelijke werkmap, zodat je de oplossing kunt copy‑paste in je eigen project en direct kunt aanpassen. Er is geen externe documentatie nodig—alles wat je nodig hebt staat hier.

## Wat je zult leren

* Hoe je **use smart markers** kunt gebruiken om een sjabloon‑werkblad te dupliceren voor elke rij in een master‑dataset.  
* Hoe je de naam van elk nieuw blad dynamisch instelt op basis van een veldwaarde (bijv. `Order_123`).  
* Hoe je een Java‑collectie voedt als de **process data source** voor de smart marker‑engine.  
* Tips voor het omgaan met randgevallen zoals lege data, speciale tekens in bladnamen, en prestatie‑overwegingen voor grote datasets.

### Vereisten

| Vereiste | Reden |
|-------------|--------|
| Java 8 of hoger | Aspose.Cells for Java ondersteunt Java 8+. |
| Maven of Gradle build‑systeem | Vereenvoudigt het toevoegen van de Aspose.Cells‑dependency. |
| Basiskennis van Java‑collecties | Nodig om de data source voor de smart markers op te bouwen. |
| Een sjabloon‑Excel‑bestand (`Template.xlsx`) met een placeholder smart marker in cel **A1** | Het sjabloon stuurt de detail‑bladgeneratie aan. |

> **Pro tip:** Houd de sjabloon‑werkmap in de `resources`‑map van het project zodat deze wordt meegeleverd met je JAR.

## Stap 1: Voeg Aspose.Cells toe aan je project (java create worksheets)

Als je **Maven** gebruikt, voeg dan de volgende dependency toe aan `pom.xml`:

```xml
<dependency>
    <groupId>com.aspose</groupId>
    <artifactId>aspose-cells</artifactId>
    <version>24.9</version> <!-- Use the latest stable version -->
</dependency>
```

Voor **Gradle**, plaats deze regel in `build.gradle`:

```gradle
implementation 'com.aspose:aspose-cells:24.9'
```

Deze regels maken de **java create worksheets**‑API’s beschikbaar tijdens het compileren.

## Stap 2: Laad de sjabloon‑werkmap

```java
import com.aspose.cells.*;

public class DuplicateDetailSheets {
    public static void main(String[] args) throws Exception {
        // Load the template workbook located in the resources folder
        Workbook workbook = new Workbook(
            DuplicateDetailSheets.class.getResource("/Template.xlsx").getPath()
        );
```

*Waarom dit belangrijk is:* Het `Workbook`‑object is het toegangspunt voor alle Excel‑bewerkingen. Het laden van het sjabloon zorgt ervoor dat je begint met de juiste lay-out en eventuele vooraf gedefinieerde opmaak.

## Stap 3: Voeg een smart marker toe die een nieuw blad maakt per master‑rij (use smart markers)

```java
        // Get the first worksheet (index 0) where the smart marker will be placed
        Worksheet worksheet = workbook.getWorksheets().get(0);

        // Insert a smart marker that tells Aspose.Cells to create a new detail sheet
        // for each row in the "Orders" collection. The new sheet name is based on
        // the OrderId field, e.g., "Order_123".
        worksheet.getCells().putValue(
            "A1",
            "${Orders:DetailSheetNewName=Order_${OrderId}}"
        );
```

De `${Orders:DetailSheetNewName=Order_${OrderId}}`‑syntaxis is de kern van **use smart markers**. Het doet drie dingen:

1. Itereert over de `Orders`‑collectie.  
2. Maakt een **new worksheet** aan voor elk element.  
3. Stelt de **sheet name from field** `OrderId` in (voorafgegaan door `Order_`).

## Stap 4: Bereid de data source voor (process data source)

Hieronder staat een minimaal voorbeeld met een `List<Map<String, Object>>`. Vervang dit door je echte data source—databaseregels, JSON‑deserialisatie, enz.

```java
        // Simulated data source: a list of orders, each represented as a map
        List<Map<String, Object>> orders = new ArrayList<>();

        Map<String, Object> order1 = new HashMap<>();
        order1.put("OrderId", 101);
        order1.put("Customer", "Acme Corp");
        order1.put("Amount", 2500.75);
        orders.add(order1);

        Map<String, Object> order2 = new HashMap<>();
        order2.put("OrderId", 102);
        order2.put("Customer", "Beta Ltd");
        order2.put("Amount", 1800.00);
        orders.add(order2);

        // Wrap the list in a data source object that Aspose.Cells can consume
        // The key "Orders" matches the smart marker name used in Step 3.
        HashMap<String, Object> dataSource = new HashMap<>();
        dataSource.put("Orders", orders);
```

*Waarom dit belangrijk is:* De **process data source**‑stap bindt je Java‑collectie aan de smart marker‑engine. De sleutel (`"Orders"`) moet exact overeenkomen met de smart marker‑naam.

## Stap 5: Verwerk de smart markers (process data source)

```java
        // Execute the smart marker processor – this creates the detail sheets
        worksheet.getSmartMarkerProcessor().process(dataSource);
```

Wanneer `process` wordt uitgevoerd, leest Aspose.Cells de `Orders`‑collectie, kloont het sjabloon‑werkblad voor elke invoer, en hernoemt elk blad volgens het `OrderId`‑veld. Dit is de kern van het gebruik van **process data source**.

## Stap 6: Sla de werkmap op met gedupliceerde detailbladen

```java
        // Save the workbook to the output directory
        workbook.save("DuplicatedDetailSheets.xlsx");
        System.out.println("Workbook saved successfully with " + orders.size() + " detail sheets.");
    }
}
```

Na uitvoering vind je `DuplicatedDetailSheets.xlsx` met:

* `Sheet1` – het originele sjabloon (ongewijzigd).  
* `Order_101` – detailblad voor de eerste order.  
* `Order_102` – detailblad voor de tweede order.

### Verwachte output (fragment)

| Bladnaam | A1 (smart marker) | Resulterende inhoud |
|----------|-------------------|----------------------|
| Order_101 | `${Orders:...}` | Populated with data from `order1` |
| Order_102 | `${Orders:...}` | Populated with data from `order2` |

Open het bestand in Excel om te verifiëren dat elk blad correct is benoemd en de gegevensrijen bevat.

## Omgaan met veelvoorkomende variaties en randgevallen

### Lege data source

Als `orders` leeg is, maakt de smart marker‑processor **geen nieuwe werkbladen**. Voeg een controle toe om een lege werkmap te voorkomen:

```java
if (orders.isEmpty()) {
    System.out.println("No orders to process – workbook will contain only the template.");
} else {
    worksheet.getSmartMarkerProcessor().process(dataSource);
}
```

### Speciale tekens in bladnamen

Excel‑bladnamen mogen geen `\ / ? * [ ] :` bevatten. Reinig het veld voordat je het gebruikt:

```java
String safeName = ("Order_" + orderId).replaceAll("[\\\\/:*?\\[\\]]", "_");
```

### Grote datasets

Voor duizenden rijen, overweeg het verhogen van de JVM‑heap (`-Xmx2g`) en roep `workbook.calculateFormula()` pas aan nadat alle bladen zijn gegenereerd om de prestaties te verbeteren.
