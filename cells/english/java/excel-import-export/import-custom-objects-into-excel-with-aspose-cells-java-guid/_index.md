# Import custom objects into Excel with Aspose.Cells – Java guide

If you need to **import custom objects** into an Excel worksheet, this guide walks you through the complete process using Aspose.Cells for Java. You’ll see how to **import data to Excel**, apply a bold header style, and generate a ready‑to‑share `.xlsx` file.

Exporting tabular data from Java often involves manual cell‑by‑cell writes, which is error‑prone and hard to maintain. By leveraging the `importCustomObjects` API you avoid boilerplate code, keep your data model intact, and gain fine‑grained styling control.

In this tutorial you will:

* Build a list of Java `Map` objects that mimics a typical data table.
* Create a reusable header style (bold font) with Aspose.Cells.
* Import the custom objects into a worksheet while applying the style array.
* Save the workbook to disk and verify the result.

The only prerequisite is a Java development environment (JDK 8+ recommended) and the Aspose.Cells for Java library.

---

## What you’ll need

| Requirement | Reason |
|-------------|--------|
| JDK 8 or newer | Required to compile and run the Java code. |

| IDE or build tool (e.g., Maven, Gradle) | Simplifies dependency management and execution. |
| Write permission to a folder for the output file | The workbook is saved as `ImportWithStyle.xlsx`. |

```xml
<dependency>
    <groupId>com.aspose</groupId>
    <artifactId>aspose-cells</artifactId>
    <version>23.12</version> <!-- Use the latest stable version -->
</dependency>
```

## Step 1: Prepare the custom objects to import

The first step is to create a collection that represents the rows you want to place in Excel. In this example we use a `List<Map<String,Object>>` where each map acts like a row with column names as keys.

```java
// Step 1 – Simulate a DataTable with a list of maps
List<Map<String, Object>> dataRows = new ArrayList<>();
dataRows.add(Map.of("Name", "Alice", "Score", 95));
dataRows.add(Map.of("Name", "Bob",   "Score", 82));
```

**Why this matters:**  
`importCustomObjects` expects an array of objects. By using a `Map`, you preserve column names, allowing Aspose.Cells to map them automatically to cells. This approach mirrors a typical `DataTable` in .NET or a `ResultSet` from JDBC, making the code reusable across projects.

---

## Step 2: Define a header style to apply on import

A clear header row improves readability. Aspose.Cells lets you create a `Style` object, set its font to bold, and pass it via an `ImportTableOptions` array.

```java
// Step 2 – Create a bold font style for the header row
Workbook tempWb = new Workbook(); // temporary workbook to obtain a style instance
Style headerStyle = tempWb.getWorksheets().get(0).getCells().get("A1").getStyle();
headerStyle.getFont().setBold(true);

// The ImportTableOptions API expects an array of styles; one entry per row.
// Here we provide a single style for the first row (the header).
Style[] styleArray = new Style[] { headerStyle };
```

**Why this matters:**  
If you omit the style array, the header appears in the default font, which may not stand out. By preparing the style once, you avoid repetitive calls for each row and keep the import logic clean.

---

## Step 3: Import the custom objects with the style array

Now you combine the data and style, then call `importCustomObjects`. The method places the data starting at the top‑left corner (row 0, column 0) and applies the header style automatically.

```java
// Step 3 – Import the custom objects into the target workbook
Workbook workbook = new Workbook();                     // target workbook
Worksheet sheet = workbook.getWorksheets().get(0);     // first worksheet

sheet.getCells().importCustomObjects(
        dataRows.toArray(),    // array of objects to import
        0,                     // start row (0‑based)
        0,                     // start column (0‑based)
        new ImportTableOptions().setStyleArray(styleArray));
```

**Why this matters:**  
`importCustomObjects` parses each map, creates columns based on the keys (`Name`, `Score`), and writes the values to the appropriate cells. The `ImportTableOptions` object tells Aspose.Cells to use the `styleArray` for the first row, giving you a bold header without extra code.

---

## Step 4: Save the workbook and verify the output

Finally, write the workbook to a file. The generated Excel file contains a styled header row followed by the data rows.

```java
// Step 4 – Save the workbook as an .xlsx file
String outputPath = "YOUR_DIRECTORY/ImportWithStyle.xlsx";
workbook.save(outputPath);
System.out.println("Workbook saved to: " + outputPath);
```

**Expected result:**  

| **Name** | **Score** |
|----------|----------|
| Alice    | 95       |
| Bob      | 82       |

The header cells (`Name`, `Score`) appear in bold font, matching the style defined in Step 2.

## Common variations and edge cases

| Situation | Recommended adjustment |
|-----------|------------------------|
| **Different column order** | Ensure the `Map` keys are inserted in the desired order, or use a custom POJO with annotated fields and a `PropertyDescriptor` array. |
| **Large data sets (>10 000 rows)** | Increase the `ImportTableOptions.setMemorySetting(MemorySetting.MEMORY_PREFERENCE)` to avoid `OutOfMemoryError`. |
| **Custom number formats** | Add a second `Style` in `styleArray` for the data rows, e.g., set `NumberFormat` to `"0"` for integer scores. |
| **Multiple worksheets** | Call `importCustomObjects` on each target worksheet, adjusting the start row/column as needed. |
| **Locale‑specific header text** | Populate the header row manually before import, then apply the style to the entire range using `Cells.applyStyle`. |

---

## Pro tips for a robust Java export to Excel

* **Reuse the temporary workbook** – Creating a new `Workbook` for each style adds overhead. Keep a single instance if you need multiple styles.  
* **Validate data before import** – Null values in a map become empty cells; you can replace them with defaults by preprocessing the list.  
* **Close resources** – Although Aspose.Cells manages memory internally, explicitly calling `workbook.dispose()` after saving releases native resources promptly.  
* **Set `Workbook.setForceFullCalculation(true)`** if your workbook contains formulas that must be evaluated before saving.
