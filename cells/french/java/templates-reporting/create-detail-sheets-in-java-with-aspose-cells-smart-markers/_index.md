# Créer des feuilles de détail en Java avec les smart markers d'Aspose.Cells

Si vous devez **créer des feuilles de détail** dans une application Java, ce tutoriel vous montre comment le faire avec les smart markers d'Aspose.Cells. Vous verrez un exemple complet et exécutable qui **java create worksheets**, dérive le **sheet name from field**, et **process data source** en seulement quelques lignes de code.

Le guide couvre tout, de la configuration du projet à l'enregistrement du classeur final, afin que vous puissiez copier‑coller la solution dans votre propre projet et l'adapter immédiatement. Aucune documentation externe n'est requise — tout ce dont vous avez besoin se trouve ici.

## Ce que vous apprendrez

* Comment **utiliser les smart markers** pour dupliquer une feuille de modèle pour chaque ligne d'un jeu de données maître.  
* Comment définir le nom de chaque nouvelle feuille dynamiquement en fonction d'une valeur de champ (par ex., `Order_123`).  
* Comment alimenter une collection Java comme **process data source** pour le moteur de smart markers.  
* Conseils pour gérer les cas limites tels que les données vides, les caractères spéciaux dans les noms de feuilles, et les considérations de performance pour les grands ensembles de données.

### Prérequis

| Exigence | Raison |
|-------------|--------|
| Java 8 ou supérieur | Aspose.Cells for Java prend en charge Java 8+. |
| Système de construction Maven ou Gradle | Simplifie l'ajout de la dépendance Aspose.Cells. |
| Connaissances de base des collections Java | Nécessaire pour construire la source de données pour les smart markers. |
| Un fichier Excel modèle (`Template.xlsx`) avec un smart marker de substitution dans la cellule **A1** | Le modèle pilote la génération des feuilles de détail. |

> **Astuce :** Conservez le classeur modèle dans le dossier `resources` du projet afin qu'il soit empaqueté avec votre JAR.

## Étape 1 : Ajouter Aspose.Cells à votre projet (java create worksheets)

Si vous utilisez **Maven**, ajoutez la dépendance suivante à `pom.xml` :

```xml
<dependency>
    <groupId>com.aspose</groupId>
    <artifactId>aspose-cells</artifactId>
    <version>24.9</version> <!-- Use the latest stable version -->
</dependency>
```

Pour **Gradle**, placez cette ligne dans `build.gradle` :

```gradle
implementation 'com.aspose:aspose-cells:24.9'
```

Ces lignes rendent les API **java create worksheets** disponibles lors de la compilation.

## Étape 2 : Charger le classeur modèle

```java
import com.aspose.cells.*;

public class DuplicateDetailSheets {
    public static void main(String[] args) throws Exception {
        // Load the template workbook located in the resources folder
        Workbook workbook = new Workbook(
            DuplicateDetailSheets.class.getResource("/Template.xlsx").getPath()
        );
```

*Pourquoi c'est important :* L'objet `Workbook` est le point d'entrée pour toutes les opérations Excel. Charger le modèle garantit que vous partez avec la mise en page correcte et tout formatage pré‑défini.

## Étape 3 : Insérer un smart marker qui crée une nouvelle feuille par ligne maître (use smart markers)

```java
        // Get the first worksheet (index 0) where the smart marker will be placed
        Worksheet worksheet = workbook.getWorksheets().get(0);

        // Insert a smart marker that tells Aspose.Cells to create a new detail sheet
        // for each row in the "Orders" collection. The new sheet name is based on
        // the OrderId field, e.g., "Order_123".
        worksheet.getCells().putValue(
            "A1",
            "${Orders:DetailSheetNewName=Order_${OrderId}}"
        );
```

La syntaxe `${Orders:DetailSheetNewName=Order_${OrderId}}` est le cœur de **use smart markers**. Elle réalise trois actions :

1. Parcourt la collection `Orders`.  
2. Crée une **nouvelle feuille de calcul** pour chaque élément.  
3. Définit le **sheet name from field** `OrderId` (préfixé par `Order_`).

## Étape 4 : Préparer la source de données (process data source)

Voici un exemple minimal utilisant un `List<Map<String, Object>>`. Remplacez-le par votre vraie source de données — lignes de base de données, désérialisation JSON, etc.

```java
        // Simulated data source: a list of orders, each represented as a map
        List<Map<String, Object>> orders = new ArrayList<>();

        Map<String, Object> order1 = new HashMap<>();
        order1.put("OrderId", 101);
        order1.put("Customer", "Acme Corp");
        order1.put("Amount", 2500.75);
        orders.add(order1);

        Map<String, Object> order2 = new HashMap<>();
        order2.put("OrderId", 102);
        order2.put("Customer", "Beta Ltd");
        order2.put("Amount", 1800.00);
        orders.add(order2);

        // Wrap the list in a data source object that Aspose.Cells can consume
        // The key "Orders" matches the smart marker name used in Step 3.
        HashMap<String, Object> dataSource = new HashMap<>();
        dataSource.put("Orders", orders);
```

*Pourquoi c'est important :* L'étape **process data source** lie votre collection Java au moteur de smart markers. La clé (`"Orders"`) doit correspondre exactement au nom du smart marker.

## Étape 5 : Traiter les smart markers (process data source)

```java
        // Execute the smart marker processor – this creates the detail sheets
        worksheet.getSmartMarkerProcessor().process(dataSource);
```

Lorsque `process` s'exécute, Aspose.Cells lit la collection `Orders`, clone la feuille de modèle pour chaque entrée, et renomme chaque feuille selon le champ `OrderId`. C'est le cœur de l'utilisation de **process data source**.

## Étape 6 : Enregistrer le classeur avec les feuilles de détail dupliquées

```java
        // Save the workbook to the output directory
        workbook.save("DuplicatedDetailSheets.xlsx");
        System.out.println("Workbook saved successfully with " + orders.size() + " detail sheets.");
    }
}
```

Après exécution, vous trouverez `DuplicatedDetailSheets.xlsx` contenant :

* `Sheet1` – le modèle original (inchangé).  
* `Order_101` – feuille de détail pour la première commande.  
* `Order_102` – feuille de détail pour la deuxième commande.

### Résultat attendu (extrait)

| Nom de la feuille | A1 (smart marker) | Contenu résultant |
|------------|-------------------|-------------------|
| Order_101  | `${Orders:...}`   | Rempli avec les données de `order1` |
| Order_102  | `${Orders:...}`   | Rempli avec les données de `order2` |

Ouvrez le fichier dans Excel pour vérifier que chaque feuille est correctement nommée et contient les lignes de données.

## Gestion des variations courantes et des cas limites

### Source de données vide

Si `orders` est vide, le processeur de smart markers ne crée **aucune nouvelle feuille**. Pour éviter un classeur vide, ajoutez une protection :

```java
if (orders.isEmpty()) {
    System.out.println("No orders to process – workbook will contain only the template.");
} else {
    worksheet.getSmartMarkerProcessor().process(dataSource);
}
```

### Caractères spéciaux dans les noms de feuilles

Les noms de feuilles Excel ne peuvent pas contenir `\ / ? * [ ] :`. Nettoyez le champ avant de l'utiliser :

```java
String safeName = ("Order_" + orderId).replaceAll("[\\\\/:*?\\[\\]]", "_");
```

### Grands ensembles de données

Pour des milliers de lignes, envisagez d'augmenter le tas JVM (`-Xmx2g`) et d'appeler `workbook.calculateFormula()` uniquement après la génération de toutes les feuilles afin d'améliorer les performances.
